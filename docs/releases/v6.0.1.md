# Vestige v6.0.1 release record

What was checked on the release branch before its pull request, and what to do
before installing it over an existing store.

## Checked locally on release/v6.0.1

- `python3 scripts/prepare-release.py check-version --version 6.0.1`: every
  product manifest and npm binary pin matches 6.0.1.
- `cargo fmt --all -- --check` and `cargo check --locked --workspace` after the
  version bump.
- `cargo test --manifest-path crates/strata-migrate/Cargo.toml`: 54 passed.
- `cargo test -p vestige-mcp --lib dashboard`: 24 passed.
- The dashboard: `vitest run` with 594 tests in 35 files, `svelte-check` with 0
  errors and 0 warnings, and `vite build`. The embedded build in
  `apps/dashboard/build` is rebuilt at 6.0.1.
- `npm test` in `packages/vestige-init`: 98 passed, 2 skipped.
- Operator Lite: `test_evidence_lock.py`, `test_session_hold.py` and the other
  Lite suites, `operator-gate.py corpus guardfall` with 50 of 50, and
  `operator-lite/npm/test.js`.

`test_replay.py`, `test_destructive.py` and `test_arming.py` run owner commands
or write hook files inside their throwaway homes, so they run in CI rather than
in an agent's shell. The pull request's CI runs the full matrix, including
clippy, the whole workspace test suite and the six target builds, before the
merge and the tag.

## Before installing over an existing store

Create and verify a complete Strata backup with the installed version first,
`vestige backup <new-empty-dir>`, and keep the previous binary. 6.0.1 changes no
store format.

## Publishing

`release.yml` builds and attaches the six target archives when the release is
created. npm and PyPI publishing waits for the owner's review of a dry run.
